## `spotnote()`

The only export — a single, self-contained Vite plugin. Import it as the default and add it to your `plugins` array.

```ts
import spotnote from 'spotnote';

export default defineConfig({
  plugins: [react(), spotnote()],
});
```

It takes **no options**. One call does everything:

- stamps `data-spotnote="file:line:column"` on host elements, and
- auto-injects the picker client via `transformIndexHtml`.

There are no `spotnoteBabel` / `spotnoteVue` / `spotnoteSvelte` sub-exports and no `enabled` flag — see [Migrating](#migrating-from-the-old-api) below if you're coming from an older setup.

## Behavior

| Aspect | Value | Why |
| --- | --- | --- |
| `apply` | `"serve"` | Dev only — production builds are never touched, so nothing leaks into your bundle. |
| `enforce` | `"pre"` | Runs before the framework compiler so the JSX/template stamp is in place first. |
| Scope | host elements in `.jsx` / `.tsx` / `.vue` | Components (uppercase) are skipped. |

## Plugin order

For React the order is flexible, but for Solid and Vue put `spotnote()` **before** the framework plugin so its `enforce: "pre"` stamp runs before their compiler:

```ts
plugins: [spotnote(), solid()]  // Solid
plugins: [spotnote(), vue()]    // Vue
plugins: [react(), spotnote()]  // React (either order works)
```

## Framework support

| Framework | How the stamp is added |
| --- | --- |
| React (Vite) | Standalone Babel JSX pass |
| Solid / Preact / Qwik (Vite) | Same Babel JSX pass |
| Vue (Vite) | Your app's `vue/compiler-sfc`, template elements |
| Next.js | Not Vite — on the roadmap |

## Migrating from the old API

Earlier versions exposed `spotnote({ enabled })` plus `spotnoteBabel`, `spotnoteVue`, and `spotnoteSvelte`, and wrote a manifest at build time. All of that is gone. Replace any of those with a single `spotnote()` call and drop the manifest/`enabled` wiring — dev-gating is built in via `apply: "serve"`.
