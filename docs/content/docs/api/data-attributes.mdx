---
title: Data Attributes
description: The attribute Spotnote stamps onto your elements
---

Spotnote adds a single attribute to host elements at dev time. There is no ID hash, no manifest, and no per-loop key attribute.

## `data-spotnote`

The source location of the element, as `file:line:column` relative to your project root.

```html
<button data-spotnote="pages/Products.jsx:12:4" class="chip">shoes</button>
```

- Added to **host elements only** — lowercase JSX tags and native `.vue` template elements. Components (uppercase) are skipped; the stamp lands where the DOM element is actually authored.
- For a component used in multiple places, the stamp points at the component's own source, not each call site.
- Present **in dev only**. The plugin is `apply: "serve"`, so production builds contain no `data-spotnote` attributes.

## How the picker reads it

On click, the client resolves the element with `elementsFromPoint` and walks up with `closest('[data-spotnote]')`, then parses the value into `file`, `line`, and `column` for the copied prompt.

## Repeated elements

Elements rendered from a loop share one source line, so they carry the **same** `data-spotnote` value. Rather than add a per-element key attribute, Spotnote disambiguates them at runtime by **occurrence index** — the element's position among all `[data-spotnote]` matches in DOM order.

The picked instance is recorded and named in the copied prompt (e.g. "instance 2 of 6"), so the target stays unambiguous without any extra markup or a `key` prop.
