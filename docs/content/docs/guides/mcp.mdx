## Set up

<Steps>
<Step>

### Add the server to your agent (once)

Pick your agent:

```bash tab="Claude Code"
claude mcp add --scope user spotnote -- npx -y spotnote-mcp
```

```bash tab="Codex"
codex mcp add spotnote -- npx -y spotnote-mcp
```

```json tab="Cursor" title="~/.cursor/mcp.json"
{
  "mcpServers": {
    "spotnote": { "command": "npx", "args": ["-y", "spotnote-mcp"] }
  }
}
```

```json tab="Gemini CLI" title="~/.gemini/settings.json"
{
  "mcpServers": {
    "spotnote": { "command": "npx", "args": ["-y", "spotnote-mcp"] }
  }
}
```

There's nothing else to run. The agent starts the server, and the launcher in your app connects to it on its own.

**You should see** **Connected** under [Settings → Coding agent](/guides/settings#coding-agent) once your agent is running.

</Step>
<Step>

### Ask your agent to watch

In your agent's chat or terminal:

```
Watch my Spotnote notes.
```

</Step>
<Step>

### Write notes in the browser

That's it. You stay in the browser from now on.

</Step>
</Steps>

<Callout type="info" title="Port 4848 taken?">
  Set `SPOTNOTE_PORT` to another port in both places: in the MCP server's
  environment (for Claude Code,
  `claude mcp add --scope user spotnote -e SPOTNOTE_PORT=4900 -- npx -y spotnote-mcp`;
  in a JSON config, an `"env": { "SPOTNOTE_PORT": "4900" }` entry next to `args`)
  and in the environment you start your dev server from.
</Callout>

## What happens to a note

1. **You write a note.** Within a few seconds, the agent picks it up. Its pin shows <PinIcon state="working" />.
2. **If the request is unclear,** the agent asks on the note. The pin shows <PinIcon state="asked" />. Click it and type your answer.
3. **When the agent is done,** the pin shows <PinIcon state="done" /> and the note shows a summary of what changed.

All pin marks:

| Pin | Meaning |
| --- | --- |
| <PinIcon n={1} /> | Waiting for an agent. |
| <PinIcon state="working" /> | The agent is working on it. |
| <PinIcon state="asked" /> | The agent asked you something. Answer in the panel. |
| <PinIcon state="done" /> | Done. The note shows what changed. |
| <PinIcon state="dismissed" /> | The agent won't make the change. The note shows why. |

The notes list shows the same marks and names the agent working on a note ("Claude Code is on it…").

## Stop watching

The agent keeps watching until you tell it to stop. While nothing happens, it checks in about once a minute, and each check-in uses some tokens. **Tell it to stop when you take a break.**

For one round instead of watching, ask: "Handle my Spotnote notes." The agent works through the open notes and stops.

## Details

<Accordions>
<Accordion title="What the conversation panel shows">

- Your note first, then the agent's messages and yours.
- Each agent message is labelled with the agent's name (Claude Code, Codex, …), and its mark for Claude Code, Cursor, Gemini, Windsurf and GitHub Copilot.
- While the agent works, its message shows "Thinking…" (and similar words), and there's no input until it answers.
- Messages show as Markdown: paragraphs, lists, `code` and code blocks, **bold**. Code is syntax-coloured, and markup written without backticks (`<span class="btn">`) shows as code too.
- A file the agent mentions, such as `router.jsx:28`, is a link that opens the file at that line. Which editor: [Settings → Open files in](/guides/settings#open-files-in).

</Accordion>
<Accordion title="When the agent is offline">

If spotnote-mcp isn't running, the panel says so. You can still reply: your message shows **not sent yet**, and goes to the agent once it's back.

</Accordion>
<Accordion title="When the agent moves on without finishing a note">

An agent finishes each note by resolving it, dismissing it or replying. If it moves on without doing any of these, <PinIcon state="working" /> goes away: a note your reply reopened (say, a "thanks!" on a done note) goes back to <PinIcon state="done" /> or <PinIcon state="dismissed" />, and a new note goes back to its number.

</Accordion>
<Accordion title="Where notes live">

- While spotnote-mcp runs, it holds the notes, and every browser with the app open shows the same ones.
- It saves them in `~/.spotnote/`, so they outlive your dev server, your `node_modules` and the browser tab. An agent sees them even before you open the app.
- When it isn't running, Spotnote uses your browser's own copy, as without MCP. Notes written meanwhile join the server's the next time it runs. For a note on the same element in both, the newer one wins.
- An agent only sees notes from apps inside the folder it works in.

</Accordion>
<Accordion title="Several agent sessions, and updates">

Each agent session starts its own spotnote-mcp. The first one serves the browsers, and the others pass their calls to it.

After you update Spotnote, the next session that starts takes over from one still running the old version, so you don't have to close your other sessions.

</Accordion>
<Accordion title="Tools the agent gets">

| Tool | What it does |
| --- | --- |
| `watch_notes` | Waits up to 50 seconds for notes that need the agent (new notes and your replies), then returns them. The agent calls it in a loop. |
| `list_notes` | Returns every open note. |
| `reply_note` | Writes a message to you on a note, usually a question. |
| `dismiss_note` | Closes a note without making the change, with the reason. |
| `resolve_note` | Marks a note done, with a short summary of the change. |

Each note comes with its id, its page, the same prompt that copying gives you, and the conversation so far.

</Accordion>
<Accordion title="Who can connect">

spotnote-mcp listens on `127.0.0.1:4848` only, so other devices on your network can't reach it. Browsers can only reach it from pages served on `localhost`.

</Accordion>
</Accordions>
