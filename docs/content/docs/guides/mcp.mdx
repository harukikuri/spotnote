---
title: Connect Your Agent (MCP)
description: Let Claude Code and other local agents pick up your notes, ask you questions and mark them done, while you stay in the browser.
---

The Spotnote plugin also runs an **MCP server** on your dev server. A coding agent connected to it reads your open notes directly, and marks each one done once it has made the change. So instead of copying and pasting every note, you write several notes and ask your agent once.

Copying still works as before, for agents without MCP.

## Connect

Start the dev server. Vite lists the endpoint with its other URLs:

```
  ➜  Local:   http://localhost:5173/
  ➜  Spotnote MCP: http://localhost:5173/__spotnote/mcp
```

Add it to your agent once:

```bash tab="Claude Code"
claude mcp add --transport http spotnote http://localhost:5173/__spotnote/mcp
```

Any other agent that supports MCP over HTTP can use the same URL.

<Callout type="info" title="Keep the port fixed">
  The URL contains the port. If Vite moves to another port (for example `5174`
  because `5173` is taken), the agent can't reach it. Pin the port in your Vite
  config with `server.port` and `server.strictPort: true`.
</Callout>

## Hands-free

Ask your agent once, in its terminal:

```
Watch my Spotnote notes.
```

From then on you stay in the browser:

1. Write a note. The agent picks it up within a few seconds and makes the change.
2. If the request is unclear, the agent asks on the note: its pin shows **?** and pulses. Click the pin, read the question, and type your answer in the panel.
3. When the agent is done, the pin shows **✓**, and the note shows the agent's summary of what it changed.

The agent keeps watching until you tell it to stop. While nothing happens, it checks in about once a minute, and each check-in is a short turn that uses some tokens, so tell it to stop when you're done for a while.

## Talking on a note

Once the agent has written on a note, its panel shows the conversation: your note, then the agent's and your messages. The input below sends a reply instead of editing the note, and replies aren't copied to the clipboard.

- **Not quite right?** Reply on a done note ("a bit darker"). It's open again, and a watching agent picks it up.
- **Want to start over?** Delete the note and write a new one.

You can also ask for one batch instead of watching: "Handle my Spotnote notes." The agent works through the open notes and stops.

## Where notes live

The page doesn't need to stay open. Once the app has loaded in a browser, the dev server has its notes, and anything the agent writes while the page is closed shows up the next time it opens. Restarting the dev server forgets the notes until you open the app again.

Each browser keeps its own notes ([Storage](/reference/storage)); the agent sees the notes of every browser that has opened the app since the dev server started.

## Tools

| Tool | What it does |
| --- | --- |
| `watch_notes` | Waits up to 50 seconds for notes that need the agent (new notes, and your replies), then returns them. The agent calls it in a loop. |
| `list_notes` | Returns every open note. |
| `reply_note` | Writes a message to you on a note: a question, or why the agent won't make the change. |
| `resolve_note` | Marks a note done, with a short summary of the change. |

Each note comes with its id, its page, the same prompt that copying gives you, and the conversation so far.

## Who can connect

The endpoint only answers requests made from your own machine to `localhost`. It stays closed to other devices on your network, even when you run `vite --host`.
