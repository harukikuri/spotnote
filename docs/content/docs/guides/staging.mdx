---
title: Staging Builds
description: Let designers and reviewers write notes on a staging or preview deploy, and hand them to a developer and their agent.
---

Spotnote runs only in `vite dev` by default. With the `build` option, it also runs in builds you deploy for review, such as a staging or preview environment. Anyone who opens it can write notes, and each prompt names the file, the line and the commit the build was made from.

## How it works

<video src="/staging-demo.mp4" autoPlay muted loop playsInline className="my-6 w-full rounded-lg border border-fd-border shadow-sm" />

1. **The reviewer** opens the staging site, clicks an element, writes the note and presses `Enter`. The prompt is on their clipboard.
2. They paste it where your team tracks feedback: an issue, a pull request, a chat thread.
3. **The developer** gives it to their agent, which goes straight to that file and line.

<Callout type="warn" title="Not for production">
  A build with Spotnote shows your source paths and component names to everyone who can open it. Turn it on only for builds that aren't public.
</Callout>

## Set up

<Steps>
<Step>

### List the modes to turn it on for

```ts title="vite.config.ts"
export default defineConfig({
  plugins: [react(), spotnote({ build: ['staging', 'preview'] })], // [!code highlight]
});
```

</Step>
<Step>

### Build in that mode

```bash
vite build --mode staging
```

Your production build (`vite build`, mode `production`) stays without Spotnote: never list that mode.

</Step>
</Steps>

## The commit in the prompt

The prompt has one more line than in dev, under the location:

```markdown
- file: components/ProductCard.jsx
- line: 7, column: 5
- commit: 3f38973 (the deployed build: if the file has changed since, compare with git show 3f38973:components/ProductCard.jsx)
```

Your branch may have moved on since the build, so the agent can look up the line at that commit and find it in today's code.

The commit comes from Git. Without the repository's history in the build, it's read from `GITHUB_SHA`, `VERCEL_GIT_COMMIT_SHA`, `CF_PAGES_COMMIT_SHA` or `COMMIT_REF` (Netlify).

## What's different from dev

- **No MCP.** A deployed page can't reach spotnote-mcp on your machine, so notes travel by copy and paste.
- **Notes stay in the reviewer's browser.** Others opening the site don't see them. See [Storage](/reference/storage).
- **File links don't open** your editor: there's no dev server to open them.
