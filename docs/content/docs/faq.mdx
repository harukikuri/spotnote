title: FAQ
description: Frequently asked questions about Spotnote
---

## Where are notes stored?

In your browser's `localStorage`, for the dev session. They persist across reloads but are local to your browser — nothing syncs across devices or teammates. There is no server and no database.

## Is this for staging / teammate feedback?

No. Spotnote is a **local dev-loop tool**: you run it against your own `vite dev` server to hand your coding agent an exact source location. It isn't meant to be deployed for others to leave feedback on.

## Can I use Spotnote in production?

There's nothing to disable — the plugin is `apply: "serve"`, so `vite build` never runs it. Production bundles contain no `data-spotnote` attributes and no picker code.

## Do notes survive across deploys?

No, and that's by design. Spotnote doesn't track builds or Git commits. Pins re-anchor across Hot Module Replacement during a dev session; they aren't meant to persist across deploys.

## Which frameworks are supported?

**React**, **Solid**, and **Vue** on Vite. JSX (`.jsx` / `.tsx`) is stamped by a standalone Babel pass; `.vue` templates are stamped via your app's `vue/compiler-sfc`. Next.js (non-Vite) is on the roadmap.

## Does Spotnote affect my bundle size?

No. It only runs in the dev server (`apply: "serve"`), so it adds nothing to production builds.

## Does Spotnote work with SSR / SSG?

Spotnote targets the Vite dev server, where it stamps elements and injects the picker client. It doesn't participate in production SSR/SSG output — there are no attributes or client code in your build.

## What are the prerequisites?

- **Vite** 5.0 or later
- **Node.js** 18 or later
- One of: React, Solid, or Vue
