## Setup

<Accordions type="multiple" className="bg-transparent border-0 rounded-none">
<Accordion title="Why doesn't the launcher appear?" id="why-doesnt-the-launcher-appear">

Try these in order:

1. **Use your dev server.** Spotnote runs only in `vite dev`, not in a build or `vite preview`.
2. **Check the browser console** for errors loading `virtual:spotnote-client`.
3. **Open a page that renders one of your components.** The launcher loads with the first `.jsx`, `.tsx`, `.vue`, `.svelte` or `.astro` file of yours on the page.

</Accordion>
<Accordion title="Why does hovering highlight nothing?" id="why-does-hovering-highlight-nothing">

Try these in order:

1. **Turn on selection mode.** Open the launcher. It should be yellow <LauncherIcon state="open" />, not grey <LauncherIcon state="paused" /> (paused). Or hold `Alt` / `⌥ Option`.
2. **Look at the terminal for `[spotnote] skipped …`.** That file couldn't be parsed, so its elements aren't stamped. See [Warnings](/reference/plugin-api#warnings).
3. **Check the file type.** Only `.jsx`, `.tsx`, `.vue`, `.svelte` and `.astro` files are stamped. In dev tools, look for a `data-spotnote` attribute on the element.

</Accordion>
</Accordions>

## Notes

<Accordions type="multiple" className="bg-transparent border-0 rounded-none">
<Accordion title="Why did a pin disappear after an edit?" id="why-did-a-pin-disappear-after-an-edit">

**Expected.** A note finds its element by the element's **source location** (file, line, column), plus its position for repeated elements.

| Your edit | The pin |
| --- | --- |
| Doesn't move the element's opening tag (classes, text, children) | Stays. |
| Moves the tag to another line or column (say, a new line above it) | Disappears. The note is marked **Not found** in the notes list. |

From the notes list, a **Not found** note can still be:

- **copied**: you get its last prompt, plus a line telling the agent the location may have moved;
- **deleted**: for example, once the agent has made the change.

It can't be opened. If the element comes back to the same location (say, you undo the edit), the note finds it again.

</Accordion>
<Accordion title="Where did my notes go?" id="where-did-my-notes-go">

**Check the port.** Notes are saved per browser and per address. If Vite started on `5174` because `5173` was busy, your notes are still under `5173`. See [Storage](/reference/storage).

</Accordion>
<Accordion title="Why does the prompt point at the wrong file?" id="why-does-the-prompt-point-at-the-wrong-file">

**Tell the agent which usage you mean.** You likely clicked an element from a shared component, so the location is inside that component's file. The **source path** in the prompt shows where it's used.

</Accordion>
</Accordions>

## Agents

<Accordions type="multiple" className="bg-transparent border-0 rounded-none">
<Accordion title="What happens when the agent is offline?" id="what-happens-when-the-agent-is-offline">

If spotnote-mcp isn't running, the panel says so. You can still reply: your message shows **not sent yet**, and goes to the agent once it's back.

</Accordion>
<Accordion title="Can I run several agent sessions?" id="can-i-run-several-agent-sessions">

**That's fine.** Each agent session starts its own spotnote-mcp. The first one serves the browsers, and the others pass their calls to it.

After you update Spotnote, the next session that starts takes over from one still running the old version, so you don't have to close your other sessions.

</Accordion>
<Accordion title="Does watching use tokens?" id="does-watching-use-tokens">

**Yes, a little.** While nothing happens, the agent checks in about once a minute. Tell it to stop when you take a break. For one round instead of watching, ask: "Handle my Spotnote notes."

</Accordion>
</Accordions>
