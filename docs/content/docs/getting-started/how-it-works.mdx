## Overview

Spotnote has two halves. At **dev time** the Vite plugin stamps a `data-spotnote="file:line:column"` attribute onto each host element and auto-injects a small picker client. At **runtime** that client lets you click an element, read its stamp, and copy an agent-ready prompt — the exact source location plus the element's tag, text, and computed styles.

There is no manifest, no server, and no Git dependency. Everything lives in the attribute.

## Dev time

<StampFlow />

The plugin runs with `apply: "serve"` (dev only) and `enforce: "pre"` (before the framework compiler), so the stamp is in place by the time React/Solid/Vue process the code:

- **JSX (`.jsx` / `.tsx`)** — a standalone Babel pass walks the AST and adds `data-spotnote` to every host (lowercase) element. It has no React dependency, so it works for Solid and other JSX frameworks too.
- **Vue (`.vue`)** — the plugin parses the SFC with your app's own `vue/compiler-sfc` and splices `data-spotnote` onto each native template element. No extra dependency of its own.

The value is the element's source position relative to the project root, for example `pages/Products.jsx:12:4`.

The plugin also serves a virtual module and injects it via `transformIndexHtml`, so the picker client boots automatically — you never import it.

<Callout type="info" title="No manifest, no Git">
  Earlier versions wrote a `.spotnote/manifest.json` and embedded a git hash.
  The current tool needs neither: the source location is carried directly on the
  element, resolved live in the browser.
</Callout>

## Runtime

<PickFlow />

When you click an element, the picker reads `data-spotnote` off the nearest matching ancestor (`elementsFromPoint` + `closest('[data-spotnote]')`), opens a note panel, and — on copy — builds a prompt with the file/line, the element, its text, and its current computed styles.

Pins persist in `localStorage` for your dev session and re-anchor across Hot Module Replacement: after an edit, Spotnote rebinds each pin by its `data-spotnote` value. If the element moved or was removed, the pin is dropped cleanly rather than guessing.

## Repeated elements

Elements rendered from a loop (`items.map(...)`) all share the same source line, so they carry the **same** `data-spotnote` value. Spotnote disambiguates them by **occurrence index** — the element's position among all matches in DOM order — and names the exact instance in the copied prompt (e.g. "instance 2 of 6") so your agent edits the right one.
