## Inspect mode

Enter inspect mode two ways:

- **Open the launcher** (the `+` button in the bottom-left) — inspect mode starts right away and stays on until you close it, or
- **Hold `Alt`** — a quick, momentary way to pick without opening the launcher.

An outline follows your cursor and a label shows `tag .class (file:line)` for whatever you're hovering. **Click** an element to select it — a pin drops and the note panel opens. After you add a note you stay in inspect mode, ready for the next one. **`Escape`** closes an open panel; pressed again, it pauses inspect mode.

## The launcher

The launcher is a round button in a corner of the page. Press it (`+` ↔ `×`) to open or close it: open means inspect mode is on and pins are shown; closed means both are off. It always starts closed on page load.

Opening it fans three buttons out along an arc:

- **Pause** — stop inspecting so you can use your app with the launcher and pins still showing,
- **Notes** — the list of every pin you've dropped, numbered like the pins,
- **Settings** — coming soon.

Drag the button to move it: it snaps to the nearest corner, the arc turns to face into the page, and the corner is remembered.

## Pins persist across edits

Each pin is anchored to its element's `data-spotnote` source location, so pins survive Hot Module Replacement while you work:

- Class-only or content edits keep the pin anchored — the opening tag doesn't move.
- If an edit shifts the line, Spotnote rebinds the pin to the new location.
- If the element is removed, the pin is dropped rather than reattached to the wrong node.

Pins live in `localStorage` for your dev session. There's no server and nothing syncs across browsers or teammates — this is a local dev-loop tool.

## Repeated elements

Elements rendered in a loop share one source line, so they all carry the same `data-spotnote` value. Spotnote tells them apart by **occurrence index** — position in DOM order among the matches — and records which instance you picked. The copied prompt names it explicitly (e.g. "instance 2 of 6, target the one matching the text above") so your agent edits the right one.

No `key` prop or extra attribute is required.
