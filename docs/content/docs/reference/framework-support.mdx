## Tested versions

Vite 5 or later. The end-to-end tests run an example app for each cell below.

Two things change between versions and could break Spotnote: Vite's plugin API, and the compilers Spotnote reads your files with (Vue, Svelte, Astro). So the apps cover every major of each framework, and every Vite from 5 to 8, without testing every pair:

- **Old with old, new with new.** An app on an older framework usually runs an older Vite too, so the oldest versions run on Vite 5 and the newest on Vite 8.
- **The versions in between fill the gaps.** React 18 runs on Vite 6, Vue 3.4 and Svelte 5 on Vite 7, so each Vite runs at least two frameworks.
- **Solid 1.9 twice.** Its Vite plugin needs Solid 1.9, so Solid is tested on the oldest and the newest Vite instead.
- **Astro picks its own Vite.** Each Astro major comes with one.

## Per framework

### JSX (React, Solid, …)

- Only `.jsx` and `.tsx` files are stamped. JSX written in `.js` or `.ts` files isn't.
- Lowercase tags (`<div>`) are stamped; capitalized ones (`<Card>`) are components and aren't.
- Member and namespaced tags (`<motion.div>`, `<svg:rect>`) aren't stamped.

### Vue

- `<template>` blocks in single-file components are stamped.
- Render functions (`h(...)`) aren't.
- `<component :is="…">` isn't, because its tag is decided at runtime.

### Astro

- Elements in `.astro` files are stamped, with Astro 5, 6 and 7 alike. Older versions aren't supported.
- Components (`<Card>`), `<slot>`, `<script>` and `<style>` aren't.
- Components in other frameworks inside a page are stamped as in a plain app of theirs, hydrated or not.
- Saving an `.astro` file reloads the page, so an open note panel closes.
- Add `spotnote()` under `vite.plugins` in `astro.config.mjs`.

### Svelte

- Markup elements in `.svelte` files are stamped, with Svelte 4 and Svelte 5 alike.
- Components and `<slot>` aren't. Markup you pass into a slot is stamped in the file where you wrote it.
- `<svelte:element this={…}>` isn't, because its tag is decided at runtime.
