Tested with Vite 5.

## Meta-frameworks

The frameworks above, inside these, were checked by hand on Vite 8 (the end-to-end tests run on plain Vite apps):

| Framework | Status | Where to add `spotnote()` |
| --- | --- | --- |
| SvelteKit | Works (3.1) | `vite.config.js` |
| Nuxt | Works (4.6) | `vite.plugins` in `nuxt.config.ts` |
| React Router, framework mode | Works (8.4) | `vite.config.ts` |
| SolidStart | Works (2.0) | `vite.config.ts` |
| Astro | Partly (7.4) | `vite.plugins` in `astro.config.mjs` |

In Astro, only components written in React, Vue, Svelte or Solid are stamped, not the markup of `.astro` files. The launcher needs a page with at least one hydrated island (`client:load`, …): on a page without one, no Spotnote code reaches the browser.

## Per framework

### JSX (React, Solid, …)

- Only `.jsx` and `.tsx` files are stamped. JSX written in `.js` or `.ts` files isn't.
- Lowercase tags (`<div>`) are stamped; capitalized ones (`<Card>`) are components and aren't.
- Member and namespaced tags (`<motion.div>`, `<svg:rect>`) aren't stamped.

### Vue

- `<template>` blocks in single-file components are stamped.
- Render functions (`h(...)`) aren't.
- `<component :is="…">` isn't, because its tag is decided at runtime.

### Svelte

- Markup elements in `.svelte` files are stamped, with Svelte 4 and Svelte 5 alike.
- Components and `<slot>` aren't. Markup you pass into a slot is stamped in the file where you wrote it.
- `<svelte:element this={…}>` isn't, because its tag is decided at runtime.
