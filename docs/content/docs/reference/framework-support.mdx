The frameworks above also work inside these. They render pages on the server first, so the [end-to-end tests](https://github.com/harukikuri/spotnote/tree/main/e2e) also check that the browser's page matches the server's (no hydration warnings).

## Per framework

### JSX (React, Solid, …)

- Only `.jsx` and `.tsx` files are stamped. JSX written in `.js` or `.ts` files isn't.
- HTML and SVG tags (`<div>`, `<svg>`) and custom elements (`<my-el>`) are stamped. Capitalized ones (`<Card>`) are components and aren't, and neither are other lowercase tags, such as React Three Fiber's `<mesh>`: they aren't DOM elements.
- Member and namespaced tags (`<motion.div>`, `<svg:rect>`) aren't stamped.

### Vue

- `<template>` blocks in single-file components are stamped.
- Render functions (`h(...)`) aren't.
- `<component :is="…">` isn't, because its tag is decided at runtime.

### Astro

- Elements in `.astro` files are stamped, with Astro 5, 6 and 7 alike. Older versions aren't supported.
- Components (`<Card>`), `<slot>`, `<script>` and `<style>` aren't.
- Components in other frameworks inside a page are stamped as in a plain app of theirs, hydrated or not.
- Saving an `.astro` file reloads the page, so an open note panel closes.
- Add `spotnote()` under `vite.plugins` in `astro.config.mjs`.

### Svelte

- Markup elements in `.svelte` files are stamped, with Svelte 4 and Svelte 5 alike.
- Components and `<slot>` aren't. Markup you pass into a slot is stamped in the file where you wrote it.
- `<svelte:element this={…}>` isn't, because its tag is decided at runtime.
